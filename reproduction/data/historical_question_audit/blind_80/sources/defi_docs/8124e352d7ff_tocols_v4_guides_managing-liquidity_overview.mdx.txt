This guide covers the full lifecycle of a Uniswap v4 liquidity position: minting a new position, increasing and decreasing liquidity, and collecting accrued fees. All operations go through the PositionManager contract using an encoded command system. Prerequisites Developing with Uniswap v4 requires Foundry. Use v4-template for a pre-configured project, or install manually: All examples below assume you have already imported and instantiated the PositionManager: Minting a Position Minting creates a new ERC-721 liquidity position in a specific pool and tick range. In v4, fee revenue is automatically credited when increasing liquidity. Encode actions If accrued fees fully cover the increase (rare), use CLOSE_CURRENCY instead of SETTLE_PAIR to handle any remainder: Encode parameters Parameter Type Description -------------- ----------- ----------------------------------------------------- tokenId _uint256_ position identifier (ERC-721 token ID) liquidity _uint256_ amount of liquidity to add amount0Max _uint128_ maximum currency0 the caller is willing to pay amount1Max _uint128_ maximum currency1 the caller is willing to pay hookData _bytes_ arbitrary data forwarded to hook functions Submit the call Decreasing Liquidity Remove tokens from an existing position. Fee revenue is automatically debited when decreasing liquidity.
